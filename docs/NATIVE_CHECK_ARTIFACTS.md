# Native check screenshots: implementation contract

Issue109 follow-up. Implemented source, accepted binary, consumer adoption, and actual visual approval are separate milestones. This document defines the next bounded implementation; it does not claim delivery.

Canonical checks may opt into `artifacts: true`. AIH allocates a unique external staging directory for every check invocation and sets `AIH_CHECK_ARTIFACTS`; inherited values are removed even for disabled checks. Consumers explicitly bind their test output to that standard contract. AIH does not recognize product-specific environment variables.

First increment imports PNGs only: at most64 screenshots,8MiB each,64MiB aggregate; bounded directory entries,depth,path length,dimensions and pixel count. Reject traversal, symlinks, hard links, Windows reparse points, nonregular files, malformed PNGs and unsupported output. Ignore bounded ordinary non-image metadata; do not import logs, HTML, traces, arbitrary JSON/text or video. Compare opened and inspected file identity before copying. Never follow linked files.

After a successful native process and ordinary cleanliness validation, copy validated bytes into a separate controller-owned immutable directory and exclusively create a manifest. Bind actual checkout HEAD/tree before and after execution, expected validation source identity, project/task/invocation, check index/digest, canonical config, rules, plan-input/toolchain identity, exit result, timestamps, and image hashes/sizes/dimensions. Integration checks attest the actual integration checkout, not task.HeadSHA. Screenshots remain untrusted content requiring human/agent inspection.

Portable Evidence.Checks receives only a validated opaque receipt ID and manifest hash suffix. Keep legacy check strings valid, including the model's anchored batch-validation regexp. No new snapshot schema is needed. Local seal resolution validates identity and image bytes before handoff. Absolute paths, environment values and image data never enter portable state. Receipt files are availability/provenance, not browser seals or approvals; Evidence.Visual remains unchanged.

Before paid review, provide a bounded verified native-image inventory and narrowly scoped read access. Do not grant source write access or access to the entire AIH home. OpenAI's supported custom permission profiles can grant exact paths `read`; see [Permissions](https://learn.chatgpt.com/docs/permissions). Confirm actual installed CLI syntax/behavior and Claude's supported permissions before adapter changes. Unsupported access becomes a typed capability blocker, never a sandbox bypass.

Missing local artifacts after attach must be reported truthfully. Native artifact readiness selects at most one exact-input native refresh; repeated absence becomes a verification blocker without spending source FIX/Advisor budgets. Preserve mixed concrete source findings and their normal repair route. Do not route missing native screenshots to the unrelated sealed visual_capture profile based only on prose.

Causal fixtures must prove two different heads and same-head invocations cannot overwrite one another; actual checkout mismatch rejects; corrupt receipts/images/config/check/input fail; unsafe paths/links/limits fail; inherited output variables are removed; provider access is read-only; attach loss and repeated absence spend no source budget; concrete findings retain normal FIX; legacy/new compact check strings validate; and native artifacts never confer visual approval.

Use existing engine/config/provider/platform boundaries, small new helpers, and narrow callsite edits. Reconcile workflow/model edits with PR162's schema12 repair-first change. Focused pure tests and compile-only checks may run during product activity. Real-Git/helper/browser/full release tests require the existing shared heavy permit. Do not stop the consumer for acceptance or weaken mandatory real-browser gates.
